# Migration guide for v23

## API keys no longer survive native PHP serialization

This affects integrations that persist SDK resources or collections in PHP sessions, caches, or queued jobs and rely on their API keys being restored by `unserialize()`.

Native `serialize()` now replaces the API key in `Stripe\Util\RequestOptions` with a placeholder, including options attached to resources, nested objects, and collections. Deserialization discards keys embedded by older SDK versions too. You can still read restored data, but you must reattach credentials before making instance API requests:

```php
// Before
$customer = unserialize($trustedStoredCustomer);
$customer->refresh();

// After
$customer = unserialize($trustedStoredCustomer);
$customer->reattachApiKey($apiKeyFromSecureConfiguration);
$customer->refresh();
$customer->description = 'Updated description';
$customer->save();

$customers = unserialize($trustedStoredCustomerList);
$customers->reattachApiKey($apiKeyFromSecureConfiguration);
foreach ($customers->autoPagingIterator() as $customer) {
    // ...
}

$event = unserialize($trustedStoredEvent);
$event->reattachApiKey($apiKeyFromSecureConfiguration);
$relatedObject = $event->fetchRelatedObject();
```

`reattachApiKey()` also attaches credentials to nested restored objects. Each retains its saved request options, including connected-account and context settings, API version, API base, and retries. Nested objects that already have credentials keep them. Reattachment does not change the global API key, and serializing the object again omits the reattached key.

Requests before reattachment raise `Stripe\Exception\AuthenticationException` with instructions to call `reattachApiKey()`, even if a global or per-call key is supplied. Calling `reattachApiKey()` on a normal object or an already reattached object raises `Stripe\Exception\InvalidArgumentException`. Empty keys and the serialization placeholder are rejected.

Serialized payloads written by older SDK versions may still contain API keys. Replace or remove those stored payloads according to your application's storage policy.
